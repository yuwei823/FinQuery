极值只用于质量观察，不在数据层静默截断。小分母、净现金或异常历史报表可能产生很大的倍数、周转天数或负企业价值倍数；查询和展示层应结合基础量解释，必要时由用户明确指定分位数过滤。

## 3. 公式版本与重算策略

1. 每个活跃指标在统一术语表中保存 `field_id`、`sql_expression`、`invalid_when`、`period_basis` 和 `formula_version`。
2. 财报CSV字段契约变化会改变契约签名并强制重建所有受影响分片。
3. `financial_period` 与 `stock_financial_daily` 使用显式 `PIPELINE_VERSION`，构建时写临时文件，成功后原子替换生产文件。
4. 公式或适用性变化必须提升相应公式版本和流水线版本，并依次全量重建期间表、日频PIT表、运行验证器，再刷新黄金SQL快照。
5. 派生指标注册变化进入Schema索引签名，后端会重建字段检索缓存，避免查询代理继续使用旧口径。

## 4. 发布结论

P0、P1及首批17个P2指标已完成生产物化、术语注册、Schema检索接入、PIT防泄漏校验、行业适用性校验、公式恒等式校验和公开年报复算。金融企业专用指标与依赖预测、分红或股本外部数据的P3指标不在本轮发布范围内。
